# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` L72-74 | Always returns `{"status": "ok"}` without checking MongoDB connectivity. | MongoDB is down but `/health` still returns 200. | Added `client.admin.command("ping")` with try/except; raise 503 on failure. |
| 2 | `create_employee()` L79 | Race condition: check-then-insert (`find_one` then `insert_one`). Two concurrent requests with the same `emp_code` can both pass the check. | Two simultaneous POST requests for the same `emp_code` both return 201. | Removed `find_one` check; rely on the unique index on `emp_code` and catch `DuplicateKeyError` for 409. |
| 3 | `create_employee()` L82 | `created_at` set with `datetime.now()` (naive, local time) instead of UTC-aware. | Stored timestamps are wrong in any timezone != UTC. | Changed to `datetime.now(timezone.utc)`. |
| 4 | `create_employee()` L78-85 | No input validation on `emp_code` pattern, `email` format, `name`/`department` length, `shift_start != shift_end`, or `joined_on` date format. | Invalid data like `emp_code="HELLO"` is silently accepted. | Added Pydantic field validators for all constraints from the OpenAPI spec. |
| 5 | `create_employee()` L85 | Returns `created_at` as a raw datetime, not epoch milliseconds. | Client receives a datetime string instead of an integer. | Added `format_employee()` that converts `created_at` to epoch ms. |
| 6 | `list_employees()` L93 | `skip = page * page_size` should be `(page - 1) * page_size`. Page 1 skips the entire first page. | GET `/employees?page=1` returns page 2's data. | Fixed to `(page - 1) * page_size`. |
| 7 | `list_employees()` L94 | `total = db.employees.count_documents({})` counts ALL documents, ignoring the department filter. | Filtering by department still shows the total count of all employees. | Changed to `count_documents(q)` using the same filter. |
| 8 | `list_employees()` L95 | No sort by `emp_code` ascending as required by the spec. | Results come in insertion order, not sorted by `emp_code`. | Added `.sort("emp_code", ASCENDING)`. |
| 9 | `list_employees()` L95 | Returns `created_at` as datetime, not epoch milliseconds. | Client receives a datetime string. | Applied `format_employee()` to each item. |
| 10 | `list_employees()` L89 | No validation on `page_size` max (100) or `page` min (1). | `page_size=999` fetches too many results; `page=0` breaks pagination. | Used `Query(20, ge=1, le=100)` and `Query(1, ge=1)`. |
| 11 | `punch_in()` L102 | `datetime.fromtimestamp(body.punched_at / 1000)` creates a naive datetime in local time, not UTC. | Punch-in times are wrong if the server isn't in UTC. | Used `epoch_ms_to_dt()` which returns a UTC-aware datetime. |
| 12 | `punch_in()` L102-103 | No truncation of timestamps to whole seconds (R1 requires it). | Sub-second precision causes inconsistent calculations. | Added `truncate_to_seconds()` call. |
| 13 | `punch_in()` L103 | Date computed from naive local time, not IST; doesn't handle overnight shifts (R1). | An overnight-shift employee punching in after midnight gets the wrong attendance date. | Implemented `compute_attendance_date()` with IST conversion and overnight-shift logic. |
| 14 | `punch_in()` L104 | Race condition: `find_one` then `insert_one`. Concurrent punch-ins for the same date can both succeed. | Two simultaneous punch-ins for the same employee/date both return 201. | Removed `find_one` check; rely on unique compound index `(emp_code, date)` and catch `DuplicateKeyError`. |
| 15 | `punch_in()` L100-101 | No 404 check if employee doesn't exist (the `find_one` might return None, then accessing `emp["shift_start"]` crashes with 500). | POST with a non-existent `emp_code` returns 500 instead of 404. | Added explicit null check with 404 response. |
| 16 | `punch_in()` L119 | Returns an `id` field (stringified `_id`) that shouldn't exist in the API response. | Response contains an unexpected `id` field. | Removed; use `format_attendance()` which excludes `_id`. |
| 17 | `punch_in()` L65-66 | No validation on `punched_at` range (must be ≥ 100000000000) or `status` values. | Seconds-looking values or invalid statuses are silently accepted. | Added `validate_epoch_ms()` and Pydantic validator for status. |
| 18 | `list_attendance()` L144-146 | Loads ALL matching documents into memory then sorts in Python. Won't scale to 100k records. | High memory usage and slow response on large datasets. | Use DB sort, skip, limit: `.sort([...]).skip(...).limit(...)`. |
| 19 | `list_attendance()` L149 | Returns an `id` field (renamed `_id`) instead of excluding `_id` entirely. | Response contains unexpected `id` field. | Use `{"_id": 0}` projection and `format_attendance()`. |
| 20 | `list_attendance()` L148 | Doesn't convert `punch_in`, `punch_out`, and `history` datetimes to epoch ms. | Client receives raw datetime strings instead of integers. | Applied `format_attendance()` with epoch ms conversion. |
| 21 | `list_attendance()` L126-131 | No validation: `date_from > date_to` should be 422; `page_size` max 100; `status` must be valid. | Invalid filters silently accepted. | Added validation checks. |
| 22 | `compute_late_minutes()` L35 | Uses `punch_in.replace(hour=h, minute=m)` which breaks for overnight shifts where the shift start is on a different calendar day than the punch-in. | Overnight-shift employee always computed as extremely late. | Rebuilt shift_start as an IST datetime on the attendance date. |
| 23 | `compute_late_minutes()` L37 | `int()` truncates toward zero, but the spec says floor. For negative values these differ (not an issue for late, but inconsistent). Also doesn't enforce `> 10:00` strictly. | `09:40:00` should give 0 (within grace) but the `> 10` comparison is on minutes (integer division), masking edge cases at exactly 10:00. | Used `total_seconds() > 600` for the grace check and `int(seconds // 60)` for floor. |
| 24 | `compute_work_hours()` L41 | Uses Python `round()` which uses banker's rounding (round-half-to-even), not half-up as required by R4. | `round(8.125, 2)` gives `8.12` instead of `8.13`. | Used `Decimal` with `ROUND_HALF_UP`. |
| 25 | `compute_overtime()` L46-47 | Doesn't handle overnight shifts (shift_end on next day). Also doesn't enforce the ≥ 30 minute threshold (R3). | Overnight shift employees get huge negative overtime; any 5-minute overtime is counted instead of 0. | Added overnight shift detection and the `>= 30` threshold. |
| 26 | Startup (missing) | No indexes created at startup. | Queries are slow (COLLSCAN); concurrency guarantees broken; grader's explain check fails. | Added `create_indexes()` on startup with unique index on `emp_code` and compound index on `(emp_code, date)`. |

Also noted — **not a defect**: the IST constant `timezone(timedelta(hours=5, minutes=30))` is correct for representing the IST offset. Using `zoneinfo` would be more future-proof but is not required for a fixed-offset zone.

Additional defects found while completing the analytics and concurrency requirements:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 27 | `employee_monthly()` | `attendance_pct` was rounded to 2 decimals although R8 requires 4 decimals for rates. | A value such as 1/3 of working days loses the required precision. | Round the percentage half-up to 4 decimal places. |
| 28 | `department_summary()` | The aggregation started from attendance records and Python separately fetched and looped over employees; that is not a database aggregation across the collections and risks omitting no-log departments if combined incorrectly. | Seed a department employee with no logs and inspect query behavior/headcount. | Start the aggregation from eligible employees and preserve empty log lookups before grouping. |
| 29 | `late_leaderboard()` | `emp_code` was included in the `$rank` sort, so equal late-minute totals did not tie. | Give two employees the same total and request a limit that reaches their rank. | Rank only by total lateness; sort ties by code only after ranking. |
| 30 | `department_trend()` | The starter fetched logs and looped in Python instead of doing gap filling/window calculations in MongoDB; it also included records without checking whether the employee had joined by that day. | Use a missing day, weekend, or mid-range joiner; inspect that the computation is database-backed. | Use `$documents`, `$densify`, indexed lookups, and `$setWindowFields` with per-day active employees. |
| 31 | `explain_endpoint()` | Several explain branches rebuilt stale or incomplete pipelines rather than explaining the production query, and trend explain omitted gap filling/window work. | Compare an endpoint's runtime pipeline with its explain request, or inspect trend explain stages. | Share pipeline builders between runtime endpoints and explain, including matching filters and pagination. |
| 32 | Timestamp request models and `regularize_attendance()` | Pydantic's ordinary `int` conversion can accept timestamp strings/floats, and corrected instants were not truncated to whole seconds. | Submit a float/string timestamp or a timestamp with milliseconds. | Use `StrictInt`, validate epoch bounds, and truncate regularized instants before storage/calculation. |
| 33 | `list_attendance()` | Date filters accepted malformed or impossible calendar dates. | Request `date_from=2026-02-30`. | Parse strict `YYYY-MM-DD` values as real calendar dates and return 422 on failure. |
| 34 | `regularize_attendance()` | Matching history by array size did not handle missing legacy history and was weaker than comparing the observed history state. | Regularize a record with no `history`, or race two corrections. | Compare the observed history array (or its missing state) atomically while appending. |
